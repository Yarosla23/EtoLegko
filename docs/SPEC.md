# Контракт: замер скорости скачивания

Статус: контракт реализованного CLI. Код и тесты готовы; состояние публикации
отслеживается в NET-05. Решения ниже заполняют детали, которых нет в задании.

## Исходные требования

1. Консольный скрипт принимает URL ресурса.
2. Выполняет 10 последовательных запросов, каждый раз полностью получая ответ.
3. Считает среднее время запроса и общий объём скачанных данных.
4. Выводит скорость скачивания с указанными единицами измерения.
5. Решение публикуется на GitHub с README и инструкцией запуска.

Ориентир реализации — 1–2 часа, срок сдачи — два дня.

## CLI и результат

```bash
python speedtest.py "https://example.com/large-file.bin"
python speedtest.py --help
```

URL — единственный обязательный позиционный аргумент. Принимаются корректно
закодированные абсолютные HTTP/HTTPS-адреса с непустым именем хоста и допустимым
портом. Неверный URL отклоняется до обращения к сети. Дополнительные флаги
для числа запросов, выбора единиц и настройки клиента в базовый объём не входят.

При успехе stdout содержит число завершённых запросов, среднее время в секундах,
точный общий объём в байтах и скорость в MiB/s. Пример формата, не реальный замер:

```text
Requests: 10
Average request time: 0.500 s
Downloaded: 10485760 bytes
Download speed: 2.000 MiB/s
```

Время и скорость округляются до трёх знаков только при выводе.

| Код завершения | Значение |
| --- | --- |
| `0` | Успешный полный замер либо `--help` |
| `1` | Сетевая/HTTP-ошибка, неполный ответ или невозможность расчёта |
| `2` | Ошибка аргументов CLI |
| `130` | Прерывание пользователем через Ctrl+C |

Ожидаемая ошибка выводится в stderr понятным коротким сообщением без traceback.
При неудачном замере итоговый отчёт об успешной скорости не печатается.

## Загрузка

- Один замер — 10 логических GET-загрузок исходного URL. Следующая начинается
  после полного чтения и закрытия предыдущего ответа. Прогрев и повторы исключены.
- Обычные HTTP/HTTPS-редиректы обрабатываются стандартным `urllib.request`.
  Они могут создавать дополнительные HTTP-обмены внутри одной загрузки;
  их время входит в неё. Объём относится к телу конечного ответа со статусом 2xx.
- Время измеряется через `time.perf_counter()` непосредственно перед открытием
  URL и после полного чтения тела. Оно включает соединение, ожидание сервера
  и передачу данных; форматирование и печать отчёта в него не входят.
- Тело читается порциями по 64 KiB до EOF, без сохранения на диск и накопления
  целого файла в памяти. Объём — сумма длин прочитанных байтовых порций,
  без декодирования текста и распаковки содержимого.
- `Content-Length` не заменяет подсчёт байтов. Отсутствие заголовка допустимо;
  при наличии корректной длины преждевременный EOF считается ошибкой.
- Таймаут `urlopen` — 30 секунд для блокирующих сетевых операций. Это не общий
  предел времени загрузки: ресурс должен иметь конечное тело; медленный поток
  может скачиваться дольше. Сохраняются стандартные настройки TLS и прокси.
- При HTTP-ошибке, ошибке соединения, таймауте или неполном теле весь замер
  завершается сразу. Частичные данные не выдаются за результат десяти загрузок.

## Расчёты

Для десяти успешных загрузок `t_i` — длительность в секундах,
`b_i` — фактически прочитанные байты:

```text
total_seconds = sum(t_i)
average_seconds = total_seconds / 10
total_bytes = sum(b_i)
speed_mib_s = total_bytes / total_seconds / (1024 * 1024)
```

Скорость вычисляется по общим объёму и времени. Среднее отдельных скоростей
может дать другой результат и здесь не используется. `1 MiB = 1 048 576 bytes`;
MiB/s означает мебибайты в секунду. Пустые успешные ответы дают нулевой объём
и нулевую скорость при положительном суммарном времени. Неположительное
суммарное время даёт управляемую ошибку без деления на ноль.

Это оценка скачивания с выбранного сервера. Она зависит от сервера, маршрута,
TLS, прокси и задержек; она не подтверждает максимальную скорость тарифа.
