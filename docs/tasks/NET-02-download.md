# NET-02 — Последовательная загрузка

Реализовать сбор длительности и объёма по правилам раздела «Загрузка» контракта.
Изменения: `speedtest.py` и тесты загрузки в `tests/test_speedtest.py`.

## Объём

- Потоковое чтение HTTP-ответа с подсчётом байтов и освобождением ресурсов.
- Последовательный цикл измерений с `perf_counter` и сетевым таймаутом.
- Проверка полноты ответа и обработка ожидаемых ошибок на границе CLI.
- Небольшие автономные тесты с подменой ответа и часов.

## Критерии приёмки

- [x] Выполняются ровно 10 логических загрузок; каждая завершается чтением
  и закрытием ответа до начала следующей. Дополнительных попыток нет.
- [x] Тело читается порциями из контракта, целый файл не накапливается.
  Размер определяется прочитанными байтами, включая ответ без `Content-Length`.
- [x] Измерение охватывает открытие URL и полное чтение тела, а не только заголовки.
- [x] Обычный HTTP/HTTPS-редирект учитывается внутри текущей загрузки.
- [x] HTTP-ошибка, таймаут, ошибка соединения или неполное тело останавливают
  дальнейшие запросы: код `1`, понятный stderr, без успешного отчёта.
- [x] Ответ закрывается и при ошибке чтения; Ctrl+C даёт код `130` без traceback.
- [x] `download_once` возвращает данные одной загрузки, `measure_downloads`
  управляет последовательностью; обе функции работают без печати и завершения
  процесса. Ожидаемые ошибки переводятся в сообщения и коды только в `main`.
- [x] Тесты подтверждают порядок операций, объём, длительность и остановку
  после ошибки. Ruff и накопленные тесты проходят.

## Проверка

Выполнено 18.11.2026 на CPython 3.15.2.

- `.venv/bin/python -m unittest discover -s tests -v` — 13 тестов прошли:
  порядок чтения и закрытия, подсчёт байтов, время, ошибки, остановка и Ctrl+C.
- Локальный HTTP-сервер: 10 загрузок через 302 дали 10 редиректов и 10 конечных
  ответов, общий объём 30 байт. Запуск потребовал разрешения на локальные сокеты,
  запрещённые в обычной песочнице; прогон с разрешением прошёл.
- `.venv/bin/python -m ruff check .` и `format --check .` — успешно.
