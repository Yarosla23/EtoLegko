# Замер скорости скачивания

Консольный скрипт выполняет 10 последовательных GET-загрузок заданного URL,
полностью читает каждый ответ и выводит среднее время запроса, общий объём
и скорость скачивания.

Основной способ запуска — **Docker**. Команды сборки и запуска одинаковы
для Linux, macOS и Windows. Python на устройстве устанавливать не требуется:
контейнер использует Python 3.15.2; сторонние библиотеки не нужны.

## Запуск

Скачайте проект или клонируйте его репозиторий:

```bash
git clone https://github.com/Yarosla23/EtoLegko.git
cd EtoLegko
```

### Через Docker

Установите и запустите [Docker Desktop](https://docs.docker.com/desktop/)
для вашей ОС или [Docker Engine](https://docs.docker.com/engine/install/)
на Linux. Проект использует Linux-контейнеры; на Windows выберите этот режим
в Docker Desktop.

Выполняйте команды из папки проекта в терминале Linux/macOS или PowerShell
на Windows. Пользователю нужен доступ к запущенному Docker.

```bash
docker build --pull -t etolegko .
docker run --rm etolegko "https://www.python.org/static/img/python-logo.png"
```

Справка и проверка аргументов:

```bash
docker run --rm etolegko --help
```

Контейнер запускает скрипт от непривилегированного пользователя и удаляется
после завершения благодаря `--rm`. Для замера не нужны тома и публикация портов.
После изменения `speedtest.py` или файлов в `etolegko/` пересоберите образ.
В образ копируются файл запуска и пакет `etolegko`; `.dockerignore` исключает
окружения, Git, документацию и секреты из контекста.

### Напрямую через Python

Для запуска без Docker нужен Python 3.12+, рекомендуемая версия — 3.15
с актуальными исправлениями. В Linux и macOS:

```bash
python3 --version
python3 speedtest.py "https://www.python.org/static/img/python-logo.png"
```

В Windows с установленным Python Launcher:

```powershell
py -3 --version
py -3 speedtest.py "https://www.python.org/static/img/python-logo.png"
```

Если Python доступен под командой `python`, используйте её вместо `python3`
или `py -3`. Это относится и к командам проверки ниже.

Передавайте абсолютный HTTP/HTTPS-адрес конечного ресурса. URL с параметрами
заключайте в кавычки; пробелы и не-ASCII символы должны быть URL-кодированы,
международные домены — представлены в ASCII/Punycode.
Для содержательного замера выберите доступный большой файл.

Пример вывода с синтетическими значениями:

```text
Requests: 10
Average request time: 0.500 s
Downloaded: 10485760 bytes
Download speed: 2.000 MiB/s
```

## Методика

Каждая следующая загрузка начинается после полного чтения и закрытия предыдущего
ответа. Тело читается порциями по 64 KiB и не сохраняется на диск.
Время измеряется через `time.perf_counter()` от начала открытия URL до окончания
чтения тела: учитываются установка соединения, ожидание сервера и передача данных.

```text
total_seconds = сумма длительностей 10 загрузок
average_seconds = total_seconds / 10
total_bytes = сумма фактически прочитанных байтов тел
speed_mib_s = total_bytes / total_seconds / 1_048_576
```

**MiB/s — мебибайты в секунду; 1 MiB = 1 048 576 байт.** Заголовки и служебный
сетевой трафик в объём не входят. Подсчитываются байты тела, полученные HTTP-клиентом,
без текстового декодирования и распаковки сжатого содержимого. `Content-Length`
используется для проверки полноты, а не как источник объёма; его отсутствие допустимо.
Пустые успешные ответы дают нулевую скорость. Округление до трёх знаков выполняется
только при выводе.

Обычные HTTP/HTTPS-редиректы обрабатывает `urllib.request`: внутри одной логической
загрузки возможны дополнительные HTTP-обмены. Их время учитывается, объём относится
к телу конечного успешного ответа. Повторов после ошибок и прогревочных запросов нет.

Сетевой таймаут — **30 секунд на блокирующие операции**, а не на всю загрузку.
Медленный поток может скачиваться дольше; ресурс должен иметь конечное тело.
Проверка TLS и настройки прокси остаются стандартными для Python/окружения.

При HTTP-ошибке, таймауте, ошибке соединения или неполном ответе скрипт сразу
останавливается, пишет сообщение в stderr и не печатает итоговую скорость.

| Код завершения | Значение |
| --- | --- |
| `0` | Успешный замер или справка |
| `1` | Ошибка загрузки или расчёта |
| `2` | Ошибка аргументов |
| `130` | Прерывание через Ctrl+C |

Результат характеризует загрузку с конкретного сервера и зависит от задержек,
маршрута, сервера и прокси. Он не подтверждает максимальную скорость тарифа;
маленький файл особенно чувствителен к задержкам соединения.

## Проверка без внешнего интернета

После сборки образа в одном терминале создайте общую сеть и запустите
тестовый HTTP-сервер. Команды одинаковы для Linux, macOS и Windows:

```bash
docker network create etolegko-test
docker run --rm --name etolegko-source --network etolegko-test --entrypoint python etolegko -B -u -m http.server 8000 --directory /app
```

Дождитесь сообщения `Serving HTTP`, затем в другом терминале выполните замер:

```bash
docker run --rm --network etolegko-test etolegko "http://etolegko-source:8000/speedtest.py"
```

Сервер отдаёт файл из образа через внутреннюю сеть Docker; публикация портов
и подключение файлов с устройства не нужны. После проверки остановите сервер
через Ctrl+C в первом терминале и удалите тестовую сеть:

```bash
docker network rm etolegko-test
```

Автотесты в контейнере (используется скрипт из собранного образа,
тесты подключаются из текущей папки только для чтения):

```bash
docker run --rm -v "$PWD/tests:/app/tests:ro" --entrypoint python etolegko -B -m unittest discover -s tests -v
```

Или без Docker:

```bash
python3 -m unittest discover -s tests -v
```

Тесты не используют внешний интернет. Они проверяют расчёты, CLI, порядок чтения,
ошибки и полный запуск через локальный HTTP-сервер на свободном порту.
Для них среда должна разрешать локальные сокеты и дочерние процессы.
Прямой запуск проверен на Linux с CPython 3.12.16 и 3.15.2.

## Проверка стиля

Ruff — только инструмент разработки, его версия закреплена в `requirements-dev.txt`.
В Linux и macOS:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-dev.txt
.venv/bin/python -m ruff check .
.venv/bin/python -m ruff format --check .
```

В Windows (PowerShell):

```powershell
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements-dev.txt
.venv\Scripts\python.exe -m ruff check .
.venv\Scripts\python.exe -m ruff format --check .
```

## Структура

```text
speedtest.py              — файл запуска
etolegko/
    __init__.py
    cli.py                — аргументы, сценарий и консольный вывод
    downloader.py         — последовательные HTTP-загрузки
    metrics.py            — данные измерений и чистые расчёты
tests/test_speedtest.py   — тесты CLI, загрузки, расчётов и интеграции
```

Результаты передаются через небольшие неизменяемые dataclass. Модуль расчётов
не зависит от сети и CLI; загрузчик возвращает данные, CLI управляет выводом
и кодами завершения. Прежние команды запуска работают через `speedtest.py`.

Подробные границы компонентов — в [AGENTS.md](AGENTS.md), поведение —
в [контракте](docs/SPEC.md), ход выполнения — в [тикетах](docs/tasks/README.md).
